## Sequence (Non‑Negotiable)

Every bounty execution **must** follow exactly one of these two sequences.

### Standard Order (Spec → Delivery → Payment → Hash)

1. **Public spec** lives on a `bounty:` issue (this document or a child issue referencing it).
2. **Operator** delivers a **new file only** on the `master` branch (no modifications to existing files except those explicitly permitted by the issue).
3. **Counterparty** sends USDC on Base to `0xAB745e5F576667037696e78ba7dA28E193E4423D` for the exact bounty amount.
4. **Counterparty** pastes the Base transaction hash as a comment on the **same issue** within 1 hour of sending.
5. **Operator** verifies the transaction:
   - Confirm recipient = `0xAB745e5F576667037696e78ba7dA28E193E4423D`
   - Confirm asset = USDC (`0x833589fCD6eDb6E08f4c7C32D4f71b54bdA02913`)
   - Confirm amount matches the bounty quoted
   - Confirm network = Base (`eip155:8453`)
6. **Operator** closes the issue with the hash recorded in the closing comment and updates `docs/BOUNTIES.md` to append the hash, date, and file delivered.

### Reverse Order (Delivery → Spec → Payment → Hash) – for urgent fixes

1. **Operator** delivers the **new file** on `master` with an urgent label.
2. **Operator** creates or updates the `bounty:` issue within 15 minutes of delivery.
3. **Counterparty** sends USDC and pastes the hash as above.
4. **Operator** verifies and closes as above.

## Payment Rules

- **Minimum bounty**: 10 USDC
- **Maximum bounty per file**: 5,000 USDC (exceptions require a separate governance issue)
- **Gas fees** are borne by the sender; the `payTo` address receives the full stated amount.
- **Refunds**: If the hash is not pasted within 1 hour of sending, the counterparty must open a refund issue with the TX hash; refunds are processed manually within 72 hours.

---

## File Delivery Rules

- **Only new files** are accepted unless the issue explicitly permits modifications to a listed file.
- **File path** must match the issue’s `File:` field exactly.
- **File content** must pass all CI checks (lint, build, test) – if CI fails, the delivery is void and no payment is due.
- **Commit message** must include the issue number and the word `bounty`.

---

## Verification & Transparency

- Every pasted hash becomes a public record on the issue.
- The `docs/BOUNTIES.md` file serves as the canonical ledger – it is append‑only and updated only when a hash is verified.
- Anyone can independently verify any payment using the Base explorer and the asset contract.

---

## Disputes

If a hash is pasted but the operator does not verify within 24 hours, the counterparty may escalate by tagging `@bounty-admins`. If the operator verifies but the file is not delivered, the counterparty must refund within 48 hours or the operator may claw back via the multisig.

---

## Termination

This protocol remains in effect until a superseding `bounty:` issue explicitly revokes it with a 7‑day notice period. All files delivered under this version remain binding.
